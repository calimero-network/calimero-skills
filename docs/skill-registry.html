Registry Skill

Context for packing, signing and publishing Calimero apps to the App Registry with core's meroctl

What This Skill Covers

The calimero-registry skill gives your AI assistant the meroctl app publishing workflow so it can write correct signing keys, pack commands, manifests and CI workflows. meroctl (core 1.0.0-rc.24) replaces cargo-mero, mero-sign, mero-app-build, scripts/pack-component.py and calimero-registry bundle push.

One Tool

meroctl app
signer new|id, build, pack, sign, inspect, publish; no node needed
Install
curl -fsSL https://raw.githubusercontent.com/calimero-network/core/master/scripts/install.sh | sh

Install the skill

npx @calimero-network/agent-skills calimero-registry

# Recommended with Rust SDK:
npx @calimero-network/agent-skills calimero-rust-sdk calimero-registry

Publish Workflow

# 1. A signing key (once); keep it out of git
meroctl app signer new release.key

# 2. Build, write + sign manifest.json, pack (metadata from [package.metadata.calimero])
meroctl app pack logic --key release.key

# 3. Check it as a node would
meroctl app inspect logic/dist/com.yourorg.myapp-0.1.0.mpk

# 4. Publish (CALIMERO_REGISTRY_API_KEY; --org ORG with a Cloud ck_live_ key)
meroctl app publish logic/dist/com.yourorg.myapp-0.1.0.mpk

Key Rules

Signed and hashed
meroctl app pack hashes every artifact, signs the manifest and writes it first in the .mpk. Never edit a bundle after packing.
Never commit the key
The Ed25519 signing key must never be committed. In CI write it from a secret to an owner-only file (umask 077) and pass --key.
Same key, every release
The signer is half the application id: a new key publishes a different app. Without --key the development key signs, which the registry refuses.

Signing Keys

# Generate a signing key (written mode 0600)
meroctl app signer new key.json

# Its did:key signer id
meroctl app signer id key.json

# Sign a manifest.json in place (RFC 8785 canonicalization + Ed25519)
meroctl app sign manifest.json --key key.json
