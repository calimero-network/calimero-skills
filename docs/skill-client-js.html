Client JS Skill

Context for frontends and Node.js services on Calimero 1.0 with mero-js's CalimeroClient

One Client

CalimeroClient (@calimero-network/mero-js 27 and later) attests every node, seals each request end to end, signs people in with passkeys and fails over across the cluster. The v1 client (MeroJs, JSON-RPC, contexts, @calimero-network/calimero-client, mero-react) is for merod 0.x and does not work against 1.0.

import { CalimeroClient, browserPasskey, passkeyConfirm } from '@calimero-network/mero-js';

Usage Patterns

const client = await CalimeroClient.connect({
  cluster: 'eu-shared-1',
  policy: { release: { minReleaseVersion: '2.3.109' } },
});
await client.signIn(browserPasskey());

// Organizations and app instances
const { orgId: org } = await client.orgs.create({ name: 'Team' });
const { appId: app } = await client.apps.create({ name: 'kv', package: 'com.example.kv', org });

// Calls go through the app's log; views do not write
await client.apps.call({ app, method: 'set', args: { key: 'a', value: '1' } });
const { result } = await client.apps.view({ app, method: 'get', args: { key: 'a' } });

// Events
for await (const event of client.events(app)) console.log(event.kind, event.data);

v1 to Calimero 1.0

context
An app instance: client.apps.create / client.apps.list.
namespace / group
An organization / team: client.orgs, invites as tokens.
rpc.execute
client.apps.call / client.apps.view, or the generated typed client.
admin login / JWT
Passkeys (signUp / signIn); the client refreshes the session itself.
