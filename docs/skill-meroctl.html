meroctl Skill

Core 1.0's meroctl: the development cluster, signing in, apps, contexts, calls, organizations and teams

What This Skill Covers

The calimero-meroctl skill teaches your AI assistant core 1.0's meroctl, which attests every node and seals every request, so it writes commands that work on a 1.0 cluster instead of the 0.x CLI.

Command Groups

  • local: a development cluster (up, down, status, dev, test)
  • login / attest / node: sign-in, trust flags, saved nodes
  • app / context / call: packages, app instances, intents and views
  • namespace / group: organizations and teams
  • blob / file / account: data, devices, API keys
  • cloud / proxy / raw / ops

Development Cluster and Sign-in

# 3 nodes on 127.0.0.1:2501-2503, saved as the node `local`
meroctl local up
# a new file passkey signs up (development clusters only)
meroctl login --dev-passkey ./dev-passkey.json --name ada

# a real cluster: an API key and the images you trust
meroctl node add prod https://node.example.com
CALIMERO_API_KEY=cal_... meroctl --tee-profiles <profile> whoami

Core Workflow

# 1. Create an app instance (dev: --path installs the file first)
meroctl context create --name kv --path kv_store.wasm --alias kv
# real cluster: meroctl app install com.example.kv@1.0.0, then --package com.example.kv

# 2. Write (an intent)
meroctl call -c kv set --args '{"key":"hello","value":"world"}'

# 3. Read (a view)
meroctl call -c kv get --args '{"key":"hello"}' --view

Organizations and Teams

meroctl namespace create Acme  # { orgId }
meroctl namespace create-group <org-id> eng  # { teamId }
meroctl context create --name eng-kv --package com.example.kv --namespace <org-id> --group <team-id>
meroctl namespace invite <org-id> --role member --uses 1 --dev-passkey ./dev-passkey.json  # { token }

# the invitee, signed in on their own
meroctl namespace join <token>

Key Rules

--view for reads
meroctl call -c CONTEXT METHOD --args JSON is a write (an intent); add --view to read without a log entry. The context is -c, never positional.
No --group-id
context create takes --name, one of --package/--bundle/--path, and --namespace (with --group) or nothing for the personal organization.
Dev passkeys are dev only
--dev-passkey and --allow-mock work on development clusters; a real cluster takes an API key and --tee-profiles.
Register node once
local up, cloud use or node add + node use save a default node; omit --node after.
0.x is gone
context identity, peers, context sync, the JSON-RPC envelope and merobox have no 1.0 meaning; the content linter flags them.
