Node Skill

Operating a Calimero 1.0 cluster with meroctl ops

What This Skill Covers

The calimero-node skill gives your AI assistant the operator's side of core 1.0: the ops token and the operator key, every meroctl ops command, and runbooks for growing, backing up, recovering and upgrading a cluster. The Ops API has no read path into apps' data.

Covered Topics

  • ops status, ops placement, ops cluster, metrics
  • Adding, moving and removing nodes (add-node, move, remove-node)
  • Backups, restores and the recovery disk
  • Quotas, release approvals, app upgrades (ops upgrade-org)
  • Upgrading the cluster's release by adding nodes

Install

npx @calimero-network/agent-skills calimero-node

# With the binary and the CLI:
npx @calimero-network/agent-skills calimero-node calimero-merod calimero-meroctl

Operator Commands

export CALIMERO_API=https://n1.eu1.example.com/
export CALIMERO_TEE_PROFILES=<profile>
export CALIMERO_OPS_TOKEN=<ops token>
export CALIMERO_OPERATOR_KEY_FILE=./operator.key

meroctl ops status
meroctl ops add-node 4 https://n4.eu1.example.com/ --zone eu1-b # signed
meroctl ops move <instance> --replicas 2,3,4 # signed
meroctl ops backup
meroctl ops set-quotas '{"maxFileBytesPerOrg":50000000000}' # signed
meroctl ops upgrade-org <org-id> --package com.example.kv --version 1.3.0
meroctl team upgrade status <org-id> <run-id>

Key Rules

Sign decisions
The node answers 428 OPERATOR_SIGNATURE_REQUIRED; meroctl signs with --operator-key-file. Nodes hold only the public half (merod --operator-key).
New release, new nodes
A node never moves to a new mero-tee image in place: add nodes on the new release, move instances onto them, remove the old ones.
Governance
Release approvals, app upgrades and outbound approvals belong to owners unless the cluster was founded with operator for them.
