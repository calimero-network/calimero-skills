Rust SDK Skill

Context injected for building Calimero 1.0 apps with core's component SDK (calimero-sdk)

What This Skill Teaches

The calimero-rust-sdk skill gives your AI assistant the component SDK: an app is a calimero:app WebAssembly component (wasm32-wasip2) whose instances each run on their own replicated log. SDK 0.12 (calimero-storage, CRDT state, cargo mero) is gone since core 1.0.0-rc.9; apps build with core's meroctl.

Covered Topics

  • #[app::state(version = N)], #[app::logic], #[app::init], #[app::view]
  • Tables (#[derive(Record)]) and collections
  • env and guards: caller, org roles, time, ids
  • Errors and events with audiences
  • Blobs, TestApp and scenarios, upgrades
  • Building with meroctl app build, meroctl local for development

Minimal App Pattern

The skill teaches this idiomatic structure:

use calimero_sdk::prelude::*;

#[app::state(version = 1)]
pub struct Board {
  posts: UnorderedMap<String, String>,
}

#[app::logic]
impl Board {
  #[app::init]
  pub fn init() -> app::Result<Self> { Ok(Self::load()) }

  pub fn create_post(&mut self, title: String) -> app::Result<String> {
    let author = guards::require_member()?;
    let id = env::unique_id();
    self.posts.insert(&id, &title)?;
    Ok(id)
  }

  #[app::view]
  pub fn post_count(&self) -> app::Result<u64> { Ok(self.posts.len()?) }
}

Key Concepts Covered

Plain collections
One leader applies every write in log order, so state is Table, UnorderedMap, Set, Vector, Cell, Counter, PerUser: not CRDTs.
guards / env::caller()
The caller is the signed-in account; guards::require_member() and require_admin() check its organization role.
env::emit()
Emits an #[app::event] variant to an Audience once the call commits.
#[app::error]
Variant name = error code; clients see 422 APP_ERROR with { code, fields }.
Determinism
env::time_now(), env::random_bytes(), env::unique_id(); no threads, I/O or wall clock.
