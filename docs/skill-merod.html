merod Skill

The merod binary: one process is one node of a Calimero 1.0 cluster

What This Skill Covers

The calimero-merod skill gives your AI assistant every merod command and node flag, checked against merod --help of 1.0.0-rc.29: configuration, development clusters, TDX nodes with mero-kms, inspection, release attestations and job nodes. The 0.x node (swarm port, JSON-RPC, JWTs) is gone.

Covered Topics

  • merod init, config, run and every node flag (MEROD_*)
  • merod local: a development cluster in one process
  • merod inspect, kms disk-key, attest
  • Job nodes, containers, /health and metrics

Install

npx @calimero-network/agent-skills calimero-merod

# With the operator skill:
npx @calimero-network/agent-skills calimero-merod calimero-node

A Node

# development: three nodes on 127.0.0.1:2501-2503, mock attestation
merod local

# production (TDX): storage key from mero-kms, governance fixed at genesis
merod --node n1 init --node-id 1 --public-url https://n1.eu1.example.com/ --cluster eu1 \
--peers 1=https://n1.eu1.example.com/,2=https://n2.eu1.example.com/,3=https://n3.eu1.example.com/ \
--kms-url https://kms.internal.example.com/ --kms-identity /data/disk-identity \
--ops-token-sha256 "$OPS_TOKEN_SHA256" --operator-key "$OPERATOR_PUBLIC_HEX"
merod --node n1 run --bootstrap # on one founding node only

Key Rules

--dev is development only
Mock quotes, a host-chosen storage key and unsigned uploads. Never on a node with real data.
Fixed at genesis
--release-approvals, --app-upgrades, --outbound-approvals, --deployments, --deployers, --sign-up and --operator-key: the same on every founding node.
One listener
--listen (default 0.0.0.0:2528) serves the API, peers and frontends; only /health and /attestation answer in the clear.
